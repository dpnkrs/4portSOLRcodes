Phase I Extraction Corrections and Adjustments Notes

This document records how the Phase I extraction flow evolved from the
first raw de-embedding attempt to the current locked baseline.

This note is intentionally chronological. It is meant to capture:
    - what was tried
    - why it was tried
    - what the diagnostics said
    - what was kept
    - what was backed out

The goal is to preserve the engineering reasoning, not just the final code.


1. Initial baseline

The first baseline was:

    THRU_meas = E * L * E

with:

    length   = 25.44 um
    eps_eff  = 3.7245
    Zc       = 50 ohm
    alpha    = 0

The extraction then used:

    T_E = expm(0.5 * logm(T_thru / T_line))

followed by one-port and two-port de-embedding.

The first complete run reached completion, but the de-embedded Open and
Short magnitudes exceeded 0 dB in the mid and high bands. That was the
first sign that the baseline was numerically stable but not yet physically
acceptable.


2. First hypothesis: line loss and line-model mismatch

The first hypothesis was that the explicit line model was too ideal,
especially because:

    alpha = 0

would force the embedding extraction to absorb too much loss.

That motivated the first major tuning step:

    fit alpha, eps_eff, Zc band-by-band

The implemented objective combined:

    - Open / Short passivity proximity
    - Open / Short target |Gamma| ~= 1
    - Load smallness
    - straight-thru match to the explicit line
    - straight-thru return-loss suppression
    - embedding passivity sanity
    - regularization around nominal alpha / eps_eff / Zc

The useful lesson from this stage was:
    line tuning helped, but only modestly

The best-fit values stayed close to the nominal starting values, so line
model error was not the dominant root cause after the first correction.


3. Critical representation correction: S-to-ABCD

One of the most important corrections in the entire Phase I development was
the change from a chain-scattering-like conversion to the correct true ABCD
conversion.

The old form:

    T = (1/S21) * [det(S), S11; -S22, 1]

was not compatible with the rest of the derivation because the explicit
line model was constructed in true ABCD form.

The corrected form used in the final code is:

    A = ((1 + S11)*(1 - S22) + S12*S21) / (2*S21)
    B = Z0*((1 + S11)*(1 + S22) - S12*S21) / (2*S21)
    C = ((1 - S11)*(1 - S22) - S12*S21) / (2*S21*Z0)
    D = ((1 - S11)*(1 + S22) + S12*S21) / (2*S21)

This correction had a larger practical impact than fine-tuning alpha or Zc.
It made the factorization and de-embedding internally self-consistent.


4. Through-only extraction reached a plateau

After line fitting and the ABCD correction, the following pattern remained:

    - de-embedded THRUs were mostly well behaved
    - de-embedded Open / Short remained the main physical concern

This suggested:

    the thru constrains transmission adequately,
    but it does not sufficiently constrain reflection in E(f)

That diagnosis drove the next phase of development.


5. Reflective refinement using measured SOL

The next major change was to use measured Open / Short / Load to refine the
reflective part of the embedding.

The implemented strategy was:

    keep S12(E), S21(E) tied to the thru-derived embedding
    refine S11(E), S22(E) using measured SOL

The refinement objective included:

    - Open / Short passivity penalties
    - Open / Short target-magnitude penalties
    - Load magnitude penalty
    - baseline regularization toward the thru-derived E(f)
    - smoothness regularization across frequency
    - embedding-level sanity terms

This was the first stage that produced a visibly meaningful improvement in
Open / Short behavior.


6. Redundant P2 one-port standards were added deliberately

Using only P1 one-port standards left the receive-side reflection term
underconstrained.

Diagnostic evidence:
    - S22 moved more than expected
    - improvements sometimes came at the cost of degrading the THRU
    - the refinement was too one-sided

So redundant P2 Open / Short / Load measurements were added and used in the
refinement.

The practical effect was not dramatic, but it improved identifiability:

    P1 constrains one side of E
    P2 constrains the opposite side of E

This reduced one-sided over-correction and made the reflective refinement
better posed.


7. Diagnostics that governed nearly every decision

Several files became central to the decision process:

    PhaseI_ObjectiveBreakdown_<Band>.txt
    PhaseI_EmbeddingComparison_<Band>.jpg
    PhaseI_RefinementDiagnostics_<Band>.jpg
    PhaseI_RefinementSummary_<Band>.txt

The most useful diagnostic quantities were:

    - change in |S11(E)| and |S22(E)|
    - improvement in Short / Open / Load after refinement
    - change in sigma_max(E)
    - comparison of E12 versus E34 extracted from different straight THRUs
    - raw-versus-simulated error metrics

These diagnostics revealed a persistent pattern:

    transmission terms were already reasonable
    reflection terms were the true bottleneck

That observation justified focusing subsequent work on reflective
refinement and final selection rather than repeatedly retuning the line.


8. Important experiments that were tried and then reduced or rolled back

8.1 Joint shared extraction using multiple THRUs

An attempt was made to use additional THRUs jointly to identify a more
shared embedding. This did not materially improve the one-port standards
and tended to wash out the useful embedding already identified by the
primary straight-thru path.

Conclusion:
    informative, but not retained as the main extraction route

8.2 Strong embedding-level passivity penalties

More aggressive passivity penalties on E(f) were tested. These did not
resolve the Open / Short issue in a satisfactory way and could degrade the
THRUs.

Conclusion:
    reduced / rolled back

8.3 Low-order polynomial reflection refinement

A more rigid polynomial correction model was tested for S11(E) / S22(E).
It was smoother, but too inflexible and generally inferior to the smoothed
pointwise refinement.

Conclusion:
    not retained

8.4 Direct SOL passivity enforcement

Both hard clamps and softer radial passivity projections were tried.

They improved the appearance of passivity, but they also moved the result
away from:

    characterized fabricated standard

toward:

    post-corrected standard

Conclusion:
    explicitly rolled back for the final Phase I baseline


9. Why SOL passivity enforcement was rolled back

This decision is central enough to state plainly.

Phase I is intended to characterize the standards themselves after
de-embedding. Therefore a final projection of the extracted standard onto
the passive set, even if mathematically smooth, was judged too strong.

The accepted final interpretation is:

    residual non-passivity is a diagnostic of model limitation,
    not something to hide at the standard-definition stage

This is why the final baseline keeps:

    - raw de-embedded standard behavior
    - no final passivity projection
    - passivity diagnostics only as evidence of residual mismatch


10. Need for stitched full-span behavior

Once per-band extraction was stable enough, the next requirement was to
create a continuous cross-band representation for reporting and later
handoff.

Initially, stitching was only overlap-based alignment and blending for
plots. That helped continuity visually, but did not create a true global
representation.

This motivated the later stitched-fit path.


11. Bandwise winner selection

Because redundant P1 and P2 standards existed, the finalization step began
ranking both candidates per band and selecting a winner for:

    OPEN
    SHORT
    LOAD

The ranking metrics evolved to include:

    - passivity proximity
    - forward agreement with the embedding / THRU behavior
    - smoothness
    - fit consistency
    - closeness to simulated de-embedded behavior

This was an important operational step because it prevented a poor local
branch from polluting the final extracted standard passed forward.


12. Global winner path

Even after bandwise winners were in place, small cross-band inconsistencies
remained because the selected port could change from band to band.

To study that, a parallel GLOBALWIN path was added:

    choose P1 or P2 once per standard across all bands

using aggregated normalized weighted metrics.

This produced:
    - a cleaner branch for stitched fitting
    - a direct comparison against bandwise winners
    - a diagnostic indication of whether port switching itself was causing
      some of the stitched discontinuities

The bandwise winner path was kept intact. GLOBALWIN was added in parallel,
not as a destructive replacement.


13. Global stitched fitting

The stitched-fit work went through several stages.

13.1 Early stitched fit behavior

At first, the stitched fit tracked the local band results too directly. In
other cases, it over-bridged the band edges and created non-physical jumps.

This led to several corrections:

    - overlap-based complex alignment
    - robust trimming of overlap statistics
    - overlap-quality scaling
    - separate THRU handling with no gain alignment
    - balanced per-band weighting
    - global smooth fit over the union grid

13.2 Key lesson from the stitched-fit work

There is a real tension between:

    continuity across bands
    versus
    fidelity to each band's accepted measurement

Too little regularization:
    the fit simply traces local fragments

Too much regularization:
    the fit bridges away from real local behavior

The current stitched-fit implementation is therefore a compromise intended
for reporting and final handoff, not a claim that the standard is exactly a
single ideal curve.


14. THRU-specific stitched-fit adjustments

The THRU case required different treatment from SOL.

Observed issue:
    gain alignment in the overlap region could overreact to notch-like
    disturbances near high-band entry

Implemented correction:

    for THRUs, allow phase / delay alignment
    but disable gain alignment

This preserved cross-band continuity without artificially lifting or
dropping the THRU magnitude around band boundaries.

Important note:
    THRUs do not have a GLOBALWIN rejected branch analogous to SOL.
    Each THRU key is its own physical structure, not a redundant P1/P2
    measurement of the same standard.


15. Final plot and archival improvements

Later in the process, additional infrastructure was added so the output set
would be dissertation-friendly:

    - white-background plots
    - saved .fig files that reopen correctly
    - stitched full-span plots
    - GLOBALWIN plots
    - overlays of winner, rejected, stitched fit, and simulation

The saved-figure logic was corrected so figures created with hidden
visibility are temporarily made visible before `savefig`, otherwise MATLAB
reopens them invisibly.


16. What the current locked baseline means physically

The current locked Phase I baseline should be interpreted as:

    1. de-embed the fabricated standards using a measurement-led embedding
       model
    2. use THRU data to identify transmission and line behavior
    3. use measured SOL to refine reflection
    4. retain the extracted standards without post-enforced passivity
    5. generate stitched smooth fits for continuity, comparison, and
       downstream use

The stitched smooth fit is therefore:

    a regularized aggregate representation of the accepted extracted bands

and not:

    a replacement for the measured bandwise extraction itself


17. Major decisions that were kept

Retained in the final baseline:

    - explicit 25.44 um line model
    - correct ABCD conversion
    - logm/expm half-factor extraction
    - bandwise line-model fitting
    - reflective refinement using measured SOL
    - inclusion of redundant P2 standards
    - bandwise winner selection
    - parallel GLOBALWIN path
    - global stitched fits with robust overlap alignment
    - THRU-specific no-gain stitched alignment


18. Major decisions that were explicitly not kept

Not retained in the final baseline:

    - hard passive clamp of extracted standards
    - soft passive projection of final standards
    - strong embedding passivity forcing
    - polynomial-only reflection correction
    - joint shared embedding extraction as the primary route


19. Practical dissertation-level summary

If the work is described at a dissertation level, the clean narrative is:

    1. start from probe-tip-calibrated fabricated-die measurements
    2. model the residual on-die transition as symmetric embedding boxes
    3. use the measured straight-thru plus an explicit 25.44 um line model
       to identify the transmission-side embedding
    4. use measured Open / Short / Load to refine the reflective side of
       the embedding
    5. de-embed the fabricated standards band-by-band
    6. select the most reliable redundant branch per standard
    7. generate a stitched smooth full-span representation for downstream
       calibration use and reporting


20. Present status

The current Phase I extraction should now be treated as the archived
baseline for fabricated-die standard characterization unless a future,
more self-consistent embedding-level passivity model is intentionally
introduced as a new phase of work.


End of notes.
